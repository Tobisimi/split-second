# Capture and processing pipeline

How the question bank is made from the University Duel videos.

1. **Capture** (`capture.js`), run in the YouTube watch page in a browser tab that stays visible. It plays the video at 2x, finds the question box, and saves crops of each question, every green answer bar (the show's own answer) and the end-of-quarter score cards. `__udGetTranscript()` keeps YouTube's auto transcript. `__udSave(name, videoId)` downloads everything as one .tar.
2. **Processing** (`process_capture.py` with `boxtext.py`): reads each frame with Tesseract (question lines, the three options split at the bullet dots, the answer bar, the name plate, both scores), groups frames into questions and works out each score change. Output: `bank/raw/*.json`.
3. **Review** (`review_tiles.py` makes sheets of question boxes next to the answer bars). Each question gets a subject and topic, and any OCR slip or maths notation is fixed by hand. `auto_review.py` first fills in questions the show already asked in a reviewed match; its `check` list holds repeats that came with options this time, whose OCR options still need cleaning. Output: `bank/review/*.json`.
4. **Merge** (`merge_review.py` with a match config in `bank/config/`): applies the review, decides the tag and how the contestant did, and writes `bank/master/<match>.json`. A group-stage video holds two matches, so each gets its own config with a `window` of video time. In most videos the left Brain Match panel's player scores on the top row; where it is the other way round (matchday 12) the config sets `"bm_left_row": 1`.
5. **Solutions** (`solution_batches.py` splits the Applied Maths and Data Analysis questions into batches): each answer is solved independently and checked in code, then a full solution and a speed trick are written. Output: `bank/solutions/*.json`. Typed General Knowledge and Verbal Reasoning questions get accepted forms (short names, common spellings) in a solutions file with only `accept`. Then `npm run bank` and `npm run check`.
6. **Build**: `npm run bank`.

Notes from checking: the green bar always shows the show's answer, including when the player was wrong or nobody answered, so a question with a captured bar has its answer confirmed by the show. The score updates when the answer window closes.

The show sometimes puts the same question up twice in a row in Brain Match, or shows the previous question's options under a new question; the faded preview of the next question under the box tells a genuine repeat from a capture glitch. Repeats and stale options are fixed in the review.

2025 videos use the same layout, so capture, processing and review sheets work unchanged. Differences: a Sponsorships box left of the Quick Buzz question (outside the crop), options in brackets above the question, and a Brain Match ladder that climbs 2, 4, 6 and so on (config `bm_max_step`). Their configs set `"season": "25"`, so ids start with 25-, and the match name ends in ", 2025". The 2025 Final video opens with highlight clips from earlier rounds and ends with replays; only the match's own stretches are reviewed. In 2025 Brain Match videos the GK and VR quarters do not always start where the score cards suggest, so those reviews set the subject on each question. On some matchday videos the capture keeps no answer frame for the left Brain Match panel; the bar can still be read in the bottom strip of the question's last frame. Long captures are saved in 20-minute parts (`ud_<name>_p1.tar`, ...) with frame numbers that carry on across parts, so the parts can be unpacked into one folder.
